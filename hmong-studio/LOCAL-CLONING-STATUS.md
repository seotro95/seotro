# Verified local cloning implementation

Version0.6.0 uses CosyVoice3 Hmong instruct2 with each supplied male/female audio reference, without a reference transcript. The user-provided poem is not used as reference text. No API key or paid runtime service is needed.

Model source: https://huggingface.co/Xuajpaj2026/hmong-tts-weights , pinned revision5663e0df2589c2ca2403cd327a52702c3ff96e8f. The bundled manifest selects118 files (~5.43GB), avoiding optional duplicate ONNX and training artifacts. Downloader validates LFS SHA256 or Git blob SHA1, supports Range resume and rejects traversal/symlink escapes. Model code hashes are checked again before loading. Tensor checkpoints use weights_only=True; primitive epoch/step training metadata is removed only in memory. Inference YAML is selected and its constructors allowlisted before construction; training objects are not evaluated. No source/checkpoint files are rewritten.

The runtime uses offline Hub settings and local files, float32 CPU with four Torch threads by default, or CUDA AMP when a CUDA-enabled Torch runtime and GPU are available. Successful requests reuse an isolated worker and loaded model; cancellation, failure and shutdown terminate that owned worker. Supplied references are decoded to mono24kHz and limited to10 seconds for instruct2 conditioning. Up to4 acoustic reference feature sets are cached, invalidated on reference/model/frontend/device changes. Original MP3s remain unchanged. Nine style choices become actual model instructions; speed is passed to synthesis. Style strength, voice similarity and correct native pronunciation still require listening checks.

Windows installer0.4.1 uses a fresh versioned clone environment and atomically selects it only after checks pass. Existing .venv and selected runtimes are never upgraded in place. Failed/interrupted attempts preserve the previous selection; rerunning a valid installation is read-only. Installer locking blocks concurrent installs. Full fresh install, read-only reuse and selected-runtime server startup were verified on Linux; native Windows remains unrun.

Downloader0.4.2 fixes missing .part errors for cold-cache zero-byte source files. Empty artifacts are materialized locally, verified against their pinned Git blob SHA1 or LFS SHA256, then atomically promoted. Bad checksums cannot replace existing targets. A real snapshot test omitted all12 empty files, reused5.43GB of hard-linked nonempty files, disabled HTTP entirely and completed the118-file ready marker; large weight sizes, modification times and inodes were unchanged. Updating code in the same app folder preserves .data and avoids downloading already verified weights again.

Package0.4.3 adds CHAY-STUDIO.bat: a single entry point installs missing prerequisites with the existing isolated-runtime installer, then starts the app using its selected interpreter. Ready runtimes are validated read-only. The browser is opened by the server child only after uvicorn has successfully started; a failed bind/startup does not open an unrelated local page. The ZIP includes app code, both supplied audio references and all installer fixes; dependencies and model weights are downloaded automatically when missing, not bundled as Windows binaries. The same archive root Hmong-Studio-Trang allows overlaying existing installs without replacing .data.

The actual launch command was exercised using the installed isolated interpreter and real model snapshot: it served API0.4.3 with local_cloning and cosy.ready true, retained the runtime pointer byte-for-byte, performed no pip installs and shut down its owned server. Linux browser handling used a no-op system browser; separate real socket tests verified that a browser callback can make HTTP200 requests after startup and is not called after application startup failure. Native Windows execution remains unrun.

Version0.5.0 accepts up to1,000,000 characters, including SRT timing lines, and streams PCM16 mono24kHz WAV to disk up to24hours (4,147,200,044bytes). The direct legacy speech endpoint stays small; long UI jobs use file-backed generation and FileResponse with Range/HEAD support. Browser output over25MiB uses the server URL and direct download instead of a large Blob or WebAudio buffer. Boundaries and streaming were tested using synthetic audio, including a sparse1hour WAV; neither a full1million-character script nor24hours of real model output were generated.

SRT auto-detection never passes timing/index lines to synthesis. Cues must be ordered, nonoverlapping and <=24hours total. Streaming assembly writes exact gaps and cue padding. Overlong speech is fitted with FFmpeg atempo up to2x with pitch retained, otherwise fails clearly without cutting words or replacing prior output. Progress measures completed text/cues and stages, with100 reserved for a validated completed audio artifact; it does not predict elapsed time.

Version0.6.0 adds explicit standard/fast compute selection and off/light/strong cleanup. CPUfast quantizes only Linear layers in a separately cached copy of flow.decoder.estimator; original FP32 weights and the LLM/speech-token head remain unchanged. Each request restores the exact original estimator in finally, including failures; CUDA keeps existing AMP. Standard remains the default because quantized acoustics can affect timbre. Runtime reports float32_int8_flow only when it was actually used.

Cleanup is local FFmpeg: highpass55Hz, afftdn6dB(light)/12dB(strong), reference-only loudnorm -20LUFS/-2dBTP, and final peak limiter0.96 without gain boost. Filter lookahead25ms at24kHz is compensated using600 tail samples and removal of only the artificial leading delay. Every original speech frame, including the final5ms, is preserved; exact output frame count is checked before atomic promotion. Synthetic tests measured ~3.9dB50Hz rumble reduction, ~2.2dB high-frequency hiss reduction and ~0.9998 retained500/1500Hz amplitudes. This is stationary noise reduction, not separation of music/other speakers or a native pronunciation rating. Original supplied/reference files remain unchanged, cleanup profiles have separate conditioning cache keys, and postfiltering happens once after complete SRT assembly.
